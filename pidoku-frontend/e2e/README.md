# End-to-end tests

Playwright drives the real app against the real API:

- **API**: `./gradlew :pidoku-api:bootTestRun` on port 8181. It runs the API from its test
  classpath (`E2eApiApplication`) with a Testcontainers Postgres (Docker needed), the `e2e`
  profile, and today's dailies generated by the real engine before it starts taking requests. It
  runs in `pidoku-api/build/e2e`, so `pidoku-api/.env` is never loaded and nothing touches Neon.
- **Frontend**: `npm run build:e2e` (to `dist-e2e/`, never deployed) served by `vite preview` on
  port 4181, which forwards `/api` to 8181.
- **Sign-in**: the e2e build (`VITE_E2E_AUTH=1`) never loads Firebase. Each browser makes up a uid
  (in `localStorage['pidoku:e2e-uid']`) and sends `Authorization: Bearer e2e.<uid>`, which only
  the API's `e2e` profile accepts. Tests choose the uid, so two browser contexts can be the same
  player on two devices.

Every test runs at desktop and phone sizes (`desktop` and `phone` projects), in UTC.

```sh
cd pidoku-frontend
npx playwright install chromium   # once, or use a browser you have:
PLAYWRIGHT_CHROMIUM=/usr/bin/chromium npm run e2e
npm run e2e -- --project=phone tutorial   # one project, files matching "tutorial"
npm run e2e -- --ui                       # watch them run
```

Locally both servers are reused if they're already running, so keep `bootTestRun` going in another
terminal while writing tests; the first boot takes a minute or two (Gradle, the Postgres image,
generating the dailies). The database lasts as long as the API does, so tests never assume they're
the only ones to have solved a daily.

CI runs them on every pull request (the `e2e` job in `.github/workflows/ci.yml`) and keeps the
HTML report and traces of failures as an artifact.
